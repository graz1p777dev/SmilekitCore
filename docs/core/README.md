# Ядро SmileKit CRM

Логическое ядро, под которое адаптируется всё остальное. Каналы, ИИ-провайдеры
и бизнес-модули подключаются к нему как детали конструктора — и отключаются,
не задевая соседей.

## Зачем

До ядра каждый канал был отдельной вселенной: `src/lib/amocrm/bot-reply.ts`
(676 строк) и `src/lib/greenapi/bot-reply.ts` (1012 строк) содержали почти
одинаковую логику — дедупликацию вебхуков, запись истории, детект «менеджер
вмешался», аварийный выключатель, очередь на чат, бронь ответа перед отправкой.
Копии разъезжались: проверка отписки была в одном канале и отсутствовала в
другом. Третий канал означал третью копию.

Теперь это происходит один раз в ядре, а канал приносит только то, чем он
действительно отличается: **как разобрать вебхук** и **как отправить**.

## Три вида интеграций

| Вид | Что приносит | Пример |
|---|---|---|
| **Канал** (`defineChannel`) | транспорт + разбор вебхука + сценарий ответа | `src/integrations/greenapi` |
| **Модуль** (`defineModule`) | реакции на события ядра | `src/integrations/inventory` |
| **ИИ-провайдер** (`AiProvider`) | `complete` / `transcribe` / `vision` | `src/core/ai/providers/deepseek.ts` |

Состав системы виден в одном файле — `src/integrations/index.ts`. Отключить
интеграцию = убрать строку `register(...)`.

## Путь входящего сообщения

1. **Маршрут** проверяет подпись, разбирает тело провайдера в `InboundMessage`
   и зовёт `receive('greenapi', message)`. Отвечает `200` сразу — обработка идёт
   фоном.
2. **Очередь**: сообщения одного чата обрабатываются строго по очереди, всего
   не больше 4 чатов параллельно на процесс.
3. **Голосовое → текст** через `ai.transcribe` (если канал не отключил).
4. **Запись входящего** в историю. Не записалось из-за уникального id — это
   повтор вебхука, обработка прекращается.
5. **Ключ сделки**: свой (`greenapi:<телефон>`) или найденный по номеру
   в другом канале — чтобы клиент не получил вторую сделку.
6. **Сделка** заводится, если её ещё нет.
7. **Предохранители**: рубильник, вмешательство менеджера, отписка, allowlist.
8. **`intercept`** — ранняя ветка канала (у WhatsApp это чек-картинка).
9. **Этап сделки** двигается по тексту клиента — даже если бот молчит.
10. **`reply`** — сценарий возвращает список сообщений.
11. **`send`** на каждое: проверка предохранителей → бронь в истории →
    транспорт → откат брони при ошибке → событие `message.sent`.

## Инварианты

Их нарушение уже приводило к авариям на проде — менять эти места без причины
нельзя:

1. **Входящее пишется до любой логики.** Запись и есть дедупликация вебхука.
2. **Бронь исходящего — до отправки.** Эхо провайдера ищет свежую запись бота
   с тем же текстом; без брони наш же ответ опознаётся как сообщение живого
   менеджера, и бот замолкает в чате навсегда.
3. **Транспорт упал — бронь снимается.** В переписке не должно остаться
   сообщения, которого клиент не получил.
4. **Молчание бота ≠ остановка CRM.** История и этапы сделок ведутся при любом
   состоянии предохранителей.
5. **Ошибка ИИ не проваливается на другого провайдера.** Молчаливая деградация
   на другую модель уже кусала проект — провайдер упал, это видно в логах.

## Карта файлов

| Файл | Ответственность |
|---|---|
| `core/types.ts` | все контракты системы — читается как оглавление |
| `core/messaging.ts` | конвейер приёма, `send()`, объект `Chat` |
| `core/conversation.ts` | таблица переписки, дедуп, эхо, `claim`, якоря |
| `core/guards.ts` | четыре причины молчать |
| `core/ai/` | выбор провайдера + сами провайдеры |
| `core/crm.ts` | сделки, заказы, уведомления, поиск сделки по номеру |
| `core/events.ts` | шина событий |
| `core/config.ts` | `defineConfig`: env + `settings.extra` + документация |
| `core/registry.ts` | реестр интеграций |
| `core/http.ts`, `core/queue.ts`, `core/logger.ts` | общие утилиты |
| `integrations/greenapi/` | эталонный канал: transport · webhook · script · policy · receipt · followup |
| `integrations/index.ts` | манифест: что подключено |

## Что осталось вне ядра

- **amoCRM** работает по старому пути (`src/lib/amocrm/*`). Причины и план
  переноса — в [migration.md](./migration.md).
- **Бизнес-модули** (финансы, склад, зарплаты, KPI) остаются обычными
  сервисами: событий у них пока нет. Когда понадобится реакция на факты из
  каналов — это модуль на шине, а не правка канала.
