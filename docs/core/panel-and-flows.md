# Настройка из браузера: «Интеграции» и «Сценарии»

Две страницы, которые убирают деплой из повседневных задач: подключить канал,
поменять ключ модели, добавить правило «если клиент написал X — ответить и
через 10 минут напомнить». Обе доступны только владельцу.

---

## Страница «Интеграции» (`/dashboard/integrations`)

Собирается из реестра ядра — новая интеграция появляется здесь сама, как
только её объявили в `src/integrations/index.ts`. Ничего дописывать в UI не
нужно.

Что на ней есть:

- **Карточки** каналов, моделей и модулей: что настроено, чего не хватает, что
  умеет модель (тексты / речь / картинки).
- **Переменные** — прямо в карточке. Обязательные помечены звёздочкой.
- **Переключатель бота** у канала — тот же аварийный выключатель, что и
  раньше: выключен → бот молчит, но история и сделки ведутся.
- **«Проверить подключение»** — настоящий запрос к провайдеру (для Green API
  это состояние инстанса), а не проверка заполненности полей.
- **Порядок моделей** (`AI_PROVIDERS`) — какая модель отвечает первой.
- **Свои переменные** — всё, что нужно сверх объявленного интеграциями.

### Где живут значения

```
переменная из базы (введена на сайте)   ← приоритет
переменная окружения Railway            ← запасной вариант
```

Такой порядок позволил перенести настройку в браузер без «дня переключения»:
пока в базе пусто, всё работает ровно как раньше.

### Секреты

Значения с признаком «секрет» шифруются AES-256-GCM и хранятся в
`integration_variables.value_encrypted`. Ключ — `INTEGRATION_ENCRYPTION_KEY`,
единственный секрет, который остаётся в панели Railway.

- В браузер значение секрета **не отдаётся никогда** — только маска `••••4f2a`.
- Показать сохранённый секрет нельзя: забыли — вводите заново.
- Пустое поле не сохраняется: случайный «Сохранить» не сотрёт рабочий токен.
- Сменили `INTEGRATION_ENCRYPTION_KEY` — старые значения не расшифруются;
  в логах будет видно, какие именно, и их нужно ввести заново.

Без этой переменной страница работает, но секреты сохранять не даёт и честно
пишет об этом наверху.

## Страница «Сценарии» (`/dashboard/flows`)

Канва с узлами: сверху триггер «Клиент написал», под ним ветки, в каждой —
цепочка действий.

### Модель

```
Клиент написал
      │
      ├── Ветка 1: условия ──► действие ──► действие ──► …
      ├── Ветка 2: условия ──► действие ──► …
      └── Ветка 3: …
```

- Ветки проверяются **по порядку слева направо**, выигрывает **первая**, у
  которой совпали **все** условия. Это и есть if / else if.
- Действия внутри ветки выполняются сверху вниз.
- Если не совпала ни одна ветка — отвечает встроенный скрипт продаж, как
  раньше. Галка «не продолжать скрипт продаж» у ветки решает, отдавать ли ему
  ход после себя.
- Ветка без условий не срабатывает никогда: «поймать всё» должно быть
  осознанным действием, а не следствием пустой формы.

### Условия

| Поле | Оператор |
|---|---|
| Сообщение клиента | содержит · не содержит · равно · подходит под regex |
| Последний ответ бота | те же |
| Вся переписка | те же |
| Имя клиента | те же |
| — | первое сообщение в чате |

### Действия

| Действие | Что делает |
|---|---|
| **Ответить текстом** | отправляет реплику; подстановки `{{name}}`, `{{phone}}`, `{{text}}` |
| **Отправить файл** | фото, документ или голосовое (только .ogg/Opus) по ссылке |
| **Подождать** | пауза 1–1440 минут; по умолчанию отменяется, если клиент ответил сам |
| **Ответ модели** | генерирует ответ с необязательным указанием |
| **Двинуть этап сделки** | «Интерес подтверждён», «Передан менеджеру» и т.д. |
| **Уведомить менеджеров** | уведомление в CRM |
| **Дёрнуть вебхук** | POST во внешнюю систему (только публичный https/http) |

### Как это исполняется

Ветки проверяются в общем конвейере приёма — между предохранителями и
встроенным скриптом (`src/core/messaging.ts`). Отправка идёт через тот же
`chat.send`, то есть со всеми правилами ядра: молчание при вмешательстве
менеджера, бронь записи до отправки, откат при сбое.

Действие «Подождать» разрывает цепочку: остаток ветки записывается в
`flow_jobs`, а планировщик (`src/core/flow/jobs.ts`, тик раз в 30 секунд)
доигрывает его, когда пауза истекла. Перед этим он проверяет:

1. ветка ещё включена;
2. клиент не ответил сам (если галка отмены стоит);
3. боту вообще можно писать в этот чат.

Любая из проверок не прошла — шаг помечается `cancelled`, клиент не получает
сообщение «из прошлого».

### Проверка без риска

Поле **«Примерить текст клиента»** показывает, какая ветка сработала бы, —
ничего не отправляя и никуда не записывая. Полный прогон — в «Лаборатории
WhatsApp»: тот же конвейер, но без реальной отправки.

## Что нужно один раз

1. Применить миграцию `supabase/migrations/20260817120000_variables_and_flows.sql`.
2. Задать `INTEGRATION_ENCRYPTION_KEY` в Railway (длинная случайная строка).
3. Открыть «Интеграции» и перенести туда ключи из переменных окружения —
   по желанию и по одному: пока переменная не введена на сайте, берётся
   значение из Railway.

## Ограничения

- Сценарии пока только для канала WhatsApp (`greenapi`): у остальных каналов
  нет своего конвейера на ядре.
- Внутри ветки нет ветвлений и циклов — только последовательность. Для «иначе»
  заводится следующая ветка.
- Триггер один: входящее сообщение. Отложенные напоминания делаются действием
  «Подождать» внутри ветки.
